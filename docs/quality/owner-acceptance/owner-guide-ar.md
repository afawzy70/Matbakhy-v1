1. افتح نافذة خاصة (Incognito) لكل حساب.
2. حالة الفحص الأولى (J0) بتتسجّل أولًا: رقم النسخة المنشورة (`./deploy.sh status` على السيرفر).
3. لو الصفحة الرئيسية فاضية (مفيش وجبات) يبقى مواعيد الـ seed انتهت: لازم `refresh-slots.sql` (بيتنفّذ ضمن `apply`).

## 4) أول رحلة كاملة: عميل ← مطبخ ← عمليات/مالية (Pickup + كاش عند الاستلام)
التفاصيل الحرفية لكل خطوة والنتيجة المتوقعة في `generated/core-owner-acceptance-suite.md` (J0 ثم J1). الخلاصة:
1. **J0** (حالات `CFG-001`, `E2E-DISC-001`, `CFG-002`, `E2E-DISC-003`, `CFG-034`): الصفحة الرئيسية بالعربي، الوجبات ظاهرة، تسجيل دخول/خروج، مسارات `/admin` على `id.` بترجع 404.
2. **العميل** `preview-customer-1`: أضف "كشري تجريبي" للسلة (`E2E-BASKET-009`)، غيّر الاستلام/الدفع وشوف إن الإجمالي بيتحسب تاني (`E2E-BASKET-019`)، اطلب **استلام + كاش** (`E2E-ORDER-101`) واحفظ رقم الطلب وكود التسليم.
3. **المطبخ** `preview-cook-1` على `ops.`: اقبل الطلب ← جاري التحضير ← جاهز.
4. **العميل**: اعرض كود الاستلام؛ المطبخ يدخل الكود ويكمّل التسليم.
5. **العمليات/المالية** `owner-e2e-ops` و`owner-e2e-finance` (`E2E-OPS-103`): الطلب مكتمل، الإجماليات بالقروش صح، **مفيش عمولة ولا رسوم منصة**.
6. بعدها: توصيل + كاش (J2)، وديعة 50% (J3/J4)، الحواجز (J5)، المطبخ والصلاحيات (J6)، MFA (J7: السياسات تفضل OPTIONAL)، الأجهزة (J8: محتاج iPhone/Android).

## 5) تسجيل النتيجة
لكل حالة اكتب: رقم الحالة، PASS/FAIL/BLOCKED، لقطة شاشة أو رد الـ API (من غير باسورد/توكن)، وسبب أي فشل. أي FAIL بيتفتح له Issue مربوط برقم الحالة.

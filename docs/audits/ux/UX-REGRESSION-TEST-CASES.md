# UX regression test cases

Baseline and scope match the [master backlog](UX-IMPROVEMENT-BACKLOG.md). These are future acceptance cases, not blanket passing results. Only explicitly recorded diagnostic executions in evidence were run. Use synthetic accounts/data and isolated local API; never real payments or production accounts. A diagnostic that proves unwanted behavior is not an acceptance PASS.

Cross-cutting matrix: web Chromium first, then supported Firefox/WebKit; 320/390/768/1440 CSS px; Arabic RTL/English LTR; keyboard-only, 200% text and 400% reflow; empty/loading/error/conflict/offline/success. Test native Android and iOS independently with large text, TalkBack/VoiceOver, offline/foreground/kill. Automated axe is supplementary.

## Preserve working business safeguards

- UX-G01: place order at old accepted price, update meal/fees, inspect all roles and history; committed snapshot never changes. New unsubmitted quote shows current terms and explicit delta consent (UX-T001).
- UX-G02: lost placement response and application restart recover the same request/order and original accepted amount; never new key or duplicate order.
- UX-G03: active kitchen price remains distinguishable from previous actual changes with EGP and Africa/Cairo timestamps; history immutable and no scheduled/bulk/rollback scope.
- UX-G04: single kitchen/slot replacement confirmation; keep leaves cart intact; unavailable selected slot cannot add even if another slot has capacity.
- UX-G05: free launch has zero commissions/platform fees/paid ads across server, ledger and clients; optional growth remains disabled, no paid campaign or billing introduced.
- UX-G06: user B/foreign kitchen cannot access order/contact/support/finance; staff-only notes excluded from responses; logout/account switch clears private state only after confirmed outcome.
- UX-G07: D11 person-count filters remain deferred. Full catering and paid growth are not silently added.
- UX-G08: order acceptance, fulfillment, cash report, kitchen transfer acknowledgment and financial verification remain separate, truthfully named concepts.

Existing regression entrypoints: `pnpm --filter @matbakhy/customer-web test`, `pnpm --filter @matbakhy/operations-web test`, native package test, `scripts/dev.sh e2e` (fresh isolated stack), focused backend suites from affected contracts, `pnpm contract:check`, typecheck/lint/build as changes require.

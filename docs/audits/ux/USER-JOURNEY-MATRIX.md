# Matbakhy user journey matrix

Audit date: 2026-10-13. Implementation baseline: `cc52fa4224e3163677a1215dc8f63ede2a9dbe4c`, `origin/implementation/mvp`. Latest main owner commercial direction remains governing; D11 serving-person filters stay deferred, D13 changed unsubmitted quotes require explicit confirmation, D14 active/history prices remain separate. No user participants or runtime task measurements were collected by this researcher. See [research findings](UX-RESEARCH-FINDINGS.md) for stable IDs and evidence.

Twelve customer scenarios and nine kitchen evaluation rows are covered. The mission lists eight kitchen bullets; receiving and processing orders are evaluated separately to cover nine kitchen rows without inventing another product capability.

**Status legend:** implemented = inspected client/API source exists, not independently proven usable; incomplete = part of the journey exists but required UI/contract pieces missing; planned = defined direction but missing implementation; unavailable = no accessible implemented flow for that distinct job; deferred = explicitly outside current approval. All actual runtime step counts, timings, participant load/confidence and completion rates are **UNMEASURED**. “Proposed stages” below are task-level target sequences, not observed taps/screens. CODE-SUPPORTED describes source behavior; HEURISTIC describes suspected user consequences; UNVERIFIED applies to live usability/accessibility across all rows until exercised. No screens are inferred from planned URLs: web actually uses hash routes; operations uses in-memory tabs.

4. Keep price-change disclosure, explicit acceptance, pending-order recovery, single kitchen/slot confirmation, immutable placed prices and active/history distinction. Regression cases include all of them even when not defective.

6. Conduct the proposed research protocol only after recruitment/consent/environment prerequisites exist. All metrics start as NOT_MEASURED; prioritize observed failures without fabricated conversion benefits.

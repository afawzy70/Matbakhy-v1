# دليل المصطلحات الهندسية بالعربي المصري

المرجع الدلالي هو النسخة الإنجليزي من Developer Handbook. الدليل ده للتحرير والمراجعة، ومش بديل لأسامي الحقول أو الحالات أو النصوص المنقولة حرفيًا من الواجهة. [تقرير المراجعة](egyptian-arabic-editorial-review.md).

| المصطلح | الصياغة المفضّلة حسب السياق | الفرق اللي لازم يفضل واضح |
|---|---|---|
| Order | طلب؛ و«أوردر» طبيعي في شرح رحلة الطلب والكود | طلب HTTP يفضل Request لما ممكن يتلخبط مع أوردر |
| Kitchen | مطبخ | مالك المطبخ هو الطبّاخ في النموذج الحالي؛ ماتخترعش دور موظف مطبخ |
| Customer | عميل | Client تقني = تطبيق العميل أو الـ Client، مش الشخص |
| Cook | طبّاخ / مالك المطبخ حسب السياق | نص «الطاهي» المنقول من الواجهة يفضل زي ما هو |
| Preview | بيئة المعاينة (Preview)، وبعدها بيئة المعاينة | مش بيئة Staging، ومش بيئة الإنتاج |
| Staging | بيئة Staging | اسم ملف أو أمر فيه staging مايثبتش إن البيئة الحالية Staging |
| Production | بيئة الإنتاج (Production) | IMPLEMENTED مش معناها شغّال في الإنتاج |
| Synthetic Data | بيانات تجريبية غير حقيقية (Synthetic Data) | مش بيانات عملاء، ومش مرادف لأي بيانات في Staging |
| Synthetic policy / values | سياسة / قيم تجريبية غير حقيقية (Synthetic) | دي إعدادات للاختبار؛ مش سياسة تجارية معتمدة |
| Fake provider / adapter | مزوّد / Adapter وهمي للاختبار | مش خدمة حقيقية؛ حدود السماح بالبيئة تفضل زي المصدر |
| Docker Image | Docker Image؛ والجمع Docker Images | صور الوجبات والمستندات Media، ماتستخدمش نفس الوصف المبهم في النشر |
| Application rollback | الرجوع للإصدار السابق (Rollback) | رجوع Docker Images مش استرجاع قاعدة البيانات |
| Restore | استرجاع البيانات من نسخة احتياطية (Restore) | فقد البيانات المكتوبة بعد النسخة الاحتياطية لازم يفضل مذكور |
| Backup | نسخة احتياطية (Backup) | وجود ملف النسخة مش دليل لوحده على نجاح الاسترجاع |
| Transaction rollback | التراجع عن تغييرات الـ Transaction (Rollback) | مش رجوع إصدار التطبيق ومش Restore |
| Reconciliation | مطابقة الإفادات أو مطابقة البيانات، حسب السياق | مطابقة العربون بشرية؛ مطابقة عدّادات المخزون فحص بيانات؛ ولا واحدة معناها تحقق بنكي |
| Settlement | تسوية / دفعة تسوية | تسوية عمولة المطبخ للمنصة مختلفة عن مطابقة بلاغ العربون |
| Refund | ردّ المبلغ / استرداد المبلغ حسب اتجاه العملية | استرجاع أوردر موجود (Recovery) مش رد فلوس |
| Replay | إعادة تنفيذ نفس الأمر (Replay) | مش Restart للخدمة؛ قواعد Idempotency تفضل واضحة |
| Recovery / lookup | استرجاع الأوردر الموجود / البحث عنه | مايتوصفش كاسترداد مالي |
| Lead time / cutoff | مهلة الطلب المسبق / آخر موعد لتسجيل طلب جديد | مش مدة تجهيز الأكل؛ موعد قبول المطبخ للأوردر (acceptBy) مفهوم منفصل، وحسابه مقيّد بالـ cutoff |
| Machine-readable | قابل للقراءة آليًا | ملف قابل للفحص الآلي، مش «مقروء بالآلة» |
| Green CI | فحوصات الـ CI نجحت | مش إثبات إن كل السيناريوهات أو البيئة المنشورة اتاختبرت |
| Live money gated | التعاملات المالية الحقيقية مش مفعّلة حاليًا، وتفعيلها مشروط بالمراجعات المطلوبة | ماتحذفش شروط المراجعة القانونية أو مراجعة المزوّد أو المستلم |
| Fail-safe MFA policy | لو صف السياسة مش موجود، النظام بيطبّق REQUIRED كاختيار آمن | مش مجرد فشل أو تعطيل MFA |
| Foreign object / object scope | عنصر خارج نطاق صلاحية المستخدم | مش «عنصر غريب»؛ 404 وحدود الصلاحية زي المصدر |
| Dead delivery | عملية تسليم متوقفة نهائيًا (Dead) | تشمل الفشل الدائم واستنفاد محاولات الإعادة، حسب الكود والمصدر |
| Authentication / Authorization | Authentication / Authorization؛ أو التحقق من الهوية / فحص الصلاحيات لو السياق محتاج | ماتدمجش المفهومين؛ أسماء الـ APIs والـ Claims محفوظة |
| Snapshot / revision / schema | Snapshot / إصدار (Revision) / Database Schema | سجل الأسعار التاريخي وإصدارات البيانات مختلفين عن بنية قاعدة البيانات |

حالات `IMPLEMENTED` و`PARTIALLY IMPLEMENTED` و`PLANNED` و`DISABLED` و`NOT VERIFIED` تفضل متميّزة وبنفس وسوم المصدر. ماتحوّلش وجود اختبار لادعاء نجاحه، ولا نجاح CI لموافقة بشرية.

في النص، استخدم جملة مصرية مهنية زي «لو الـ API مش بيرد، راجع حالة الـ Container وبعدها الـ Logs». حافظ على النفي والإلزام والاختيار وشروط الأمان، وعلى أمثلة الأرقام والحسابات. ماتغيّرش Code Fences أو Inline Code أو أسماء الملفات عشان اللغة أو اتجاه العرض.

الـ glossary بيسمح بصيغ سياقية سليمة، مش استبدال شامل للكلمات. بعض عناوين الأقسام القديمة اتساب زي ما هو عشان استقرار الـ Anchors، والنصوص المحمية جوه الرسومات اتسابت حرفيًا. ده مايسمحش بخلط المفاهيم في الشرح.

قواعد مقترحة لمسؤول `ai-skills/developer-handbook`: قراءة الزوج كامل قبل التحرير؛ مراجعة مستقلة لكل جزء اتعدّل؛ قائمة مصطلحات سياقية؛ فحص النص المحمي مقابل الـ baseline؛ حفظ أدلة الملف والقسم وقبل/بعد والسبب والخطورة؛ تشغيل parity وDOC-001 بعد تحديث سجل المراجعة. مسار المهارة مش موجود في الـ baseline ده؛ مفيش ملفات مهارة اتعملت أو اتعدّلت.

### Why OAuth is not usable here

`kane-cli login --oauth` opens a local browser and waits for a callback on this machine. A headless cloud container has neither. The documented non-interactive path is basic auth (TestMu username + access key), the same as for CI.

### Owner action to unblock

1. In TestMu AI, sign in on the free tier and copy the access key from profile/account settings. Do not buy a plan or enable overages.
2. In this cloud environment's settings (environment menu → Edit), add environment variables `LT_USERNAME` and `LT_ACCESS_KEY`. Never paste them into chat or the repository.
3. Start a new session. The agent passes `--username "$LT_USERNAME" --access-key "$LT_ACCESS_KEY"` per run and never prints them.

What leaves the machine: by default each Kane run is uploaded to the TestMu account as a Test Manager test case with screenshots. Only synthetic local data may be used.

## Test cases (Kane objectives)

Run with `--url http://localhost:5173/ --headless --timeout 300`. The customer web defaults to Arabic; the English strings below come from `apps/customer-web/src/i18n.ts`.

### TC-K1 — Browse meals (D11, D12, BR-017)

Objective: Open the home page, choose the synthetic zone, list meals, and inspect the meal cards and filter controls.

Expected:
1. Meals A1, A2 and B1 are listed, each with a kitchen name, an integer EGP price and an availability state.
2. A1's card shows its published description. A2's card shows no description, placeholder or empty gap (D12).
3. Meal X1 is not offered for purchase (BR-017).
4. No "one person" / "two people" portion filter control is visible, and no sort control is labelled as a portion filter (D11).

### TC-K2 — Add to basket

Objective: Open meal A1, choose slot S1, quantity 1, click "Add to cart" (أضف إلى السلة), then open the cart.

Expected:
1. The "Added to cart." confirmation appears.
2. The cart contains exactly A1 × 1 from Kitchen A for slot S1.
3. The displayed total equals the price shown on the meal page, in EGP, no fractions.

### TC-K3 — Basket replacement (BR-018, TC-147)

Precondition: the cart holds A1 for slot S1 (TC-K2).

Objective, part a: Open meal B1 (Kitchen B), choose its slot, click "Add to cart". When a "Replace your cart?" dialog appears, click "Keep my current cart". Open the cart.

Expected (a):
1. A "Replace your cart?" (تستبدل السلة؟) dialog appears before any change, explaining one kitchen and one slot per order.
2. After "Keep my current cart", the message "Your cart is unchanged." appears and the cart still holds only A1 × 1 / Kitchen A / slot S1.

Objective, part b: Repeat adding B1 and click "Replace cart" (استبدال السلة). Open the cart.

Expected (b):
3. The cart holds only B1 from Kitchen B with B1's slot; A1 is gone.

Variant (same kitchen, other slot): with A1 in S1, add A2 for slot S2. The same dialog must appear.

## Outcome

- Three materially different harness attempts for the same iOS defect (`5efc139`, `1db23f0`, `7ce20da`). Under the execution protocol, this is now recorded as blocker **BLK-005** instead of a fourth attempt today.
- On iOS, the sign-in itself works: the API log shows SyntheticA and SyntheticB authenticated in runs 46 and 47.
- The iOS ordering, D13, large-text, refusal and **MB-053 deposit** phases were **NOT_RUN** after run 40. Run 40 at `9c0db34` passed iOS phases A–J, which included everything except the deposit phase.
- Android passed every phase in runs 43, 46 and 47 attempt 1, including the deposit phase.

## Options for the next window (no spending needed)

1. Turn off password AutoFill on the simulator before the tests, so iOS never offers to save the password.
2. Replace the polling loop with `addUIInterruptionMonitor` for the "Save Password?" alert plus one tap on the app, which lets XCTest handle the interruption itself.
3. Mark the provider's local test login form `autocomplete="off"` in the local realm theme (test realm only).
